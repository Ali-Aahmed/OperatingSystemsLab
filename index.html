١) يعني إيه Operating System؟

تخيّل فندق 🏨: النزلاء (المستخدمين) مش بيدخلوا المطبخ ولا بيظبطوا الكهربا بنفسهم، بيكلّموا موظف الاستقبال وهو اللي يدبّر كل حاجة. نظام التشغيل (OS) بالظبط كده: واقف بينك وبين الـ Hardware.

OS = برنامج وسيط بين المستخدم والـ Hardware، وهو "مدير" الكمبيوتر

أهداف الـ OS:

  • ينفّذ برامج المستخدم ويسهّل حل مشاكله.
  • يخلّي الكمبيوتر سهل الاستخدام (convenient).
  • يستخدم الـ Hardware بشكل كفء (efficient).

Hardware — الموارد الأساسية: CPU, Memory, I/O devices.

Operating System — بين البرامج والـ hardware وبيدّي وصول منظّم للموارد.

Application programs — Word, Browser, Games… بتستخدم الموارد لحل مشاكل المستخدم.

Users — ناس، أو أجهزة، أو كمبيوترات تانية.

الـ Kernel

الـ Kernel هو القلب بتاع الـ OS، وبيتحكم في الـ hardware والأجهزة الطرفية:

  • بيتحمّل أول حاجة لما الجهاز يشتغل.
  • بيفضل في الـ RAM طول الوقت.
  • بيدير الـ CPU والذاكرة والوصول للأجهزة.
💡 غير الـ Kernel فيه نوعين برامج: System programs و Application programs. يعني المتصفح مش جزء من الـ Kernel.

٤) الـ Interrupts

Interrupt = إشارة لـ CPU تقوله: "وقّف اللي بتعمله واهتم بالموضوع ده دلوقتي"

Hardware Interrupt: بييجي من جهاز (مثلاً الـ Disk خلّص قراءة).

Software Interrupt (Trap): بيحصل بسبب خطأ (قسمة على صفر، وصول غلط للذاكرة) أو طلب من برنامج لخدمة من الـ OS (System Call).

Interrupt Vector: جدول فيه عناوين كل الـ service routines، فالـ CPU بيروح للعنوان مباشرة من غير بحث.

⚠️ لازم الـ Interrupt يتعالج بسرعة، ولازم حالة الـ Process المتقطّعة تتحفظ عشان تكمّل من نفس المكان. والـ OS اسمه interrupt-driven: بيقعد مستني ويرد على الأحداث لما تيجي.

ملخص سريع قبل الأسئلة

  • OS = وسيط بين المستخدم والـ hardware. User view: سهولة، System view: إدارة موارد (Resource allocator + Control program).
  • الـ Kernel أول حاجة بتتحمّل وبتفضل في الـ RAM.
  • الـ device controller على الجهاز، والـ driver software بيكلّمه.
  • Interrupt = إشارة للـ CPU. Hardware من جهاز، Trap من خطأ أو طلب. بنوصل للـ ISR من الـ Interrupt Vector.
  • هرم التخزين: Registers ← Cache ← RAM ← SSD ← HDD ← Optical ← Tape (أسرع لأبطأ، أصغر لأكبر).
  • DMA بينقل blocks من غير الـ CPU، وبـ interrupt واحد في النهاية.
  • Boot: Power on ← Bootstrap (ROM) ← تحميل الـ Kernel ← init ← استنى حدث.

قاموس سريع

Kernel — قلب الـ OS.
ISR — الروتين اللي بيعالج الـ interrupt.
Volatile — بتفقد محتواها لما الكهربا تقطع.
Bus — مسار مشترك بيوصل الـ CPU بالذاكرة والأجهزة.
Buffer — مساحة مؤقتة جوه الـ controller.
ROM — ذاكرة للقراءة بس، بتحتفظ بمحتواها.
Trap — Interrupt بيتولّد من software.
Bootstrap — برنامج البداية المخزّن في ROM.

٤) Dual-Mode و System Calls

لو أي برنامج قدر يكلّم الـ hardware مباشرة، برنامج واحد غلطان ممكن يوقّف الجهاز. عشان كده الـ CPU فيه mode bit:

User mode: الوضع العادي للبرامج. ممنوع الـ privileged instructions.

Kernel mode: للـ OS بس. مسموح بالـ privileged instructions (I/O، التحكم في الـ interrupts، تغيير الـ mode).

لو برنامج حاول ينفّذ privileged instruction في user mode ← Trap للـ OS بدل ما تتنفّذ.

System Call = الطريقة المسموحة اللي البرنامج بيطلب بيها خدمة من الـ Kernel

ملخص سريع قبل الأسئلة

  • Batch: من غير تفاعل. Multiprogramming: أكتر من job في الـ RAM لرفع الـ utilization. Time-sharing: تبديل سريع وتفاعل online.

٢) الـ Process شكلها إيه جوه الـ RAM؟

لما الـ Process تتحمّل في الذاكرة بتتقسّم لـ 4 أجزاء:

Text الكود نفسه (الـ instructions) — ثابت وغالباً read-only.

Data المتغيرات الـ global و static.

Heap الذاكرة الديناميكية (malloc / new) — بتكبر لفوق ⬆ وإنت المسؤول تحررها.

Stack الـ local variables و parameters و return address — بتكبر لتحت ⬇ وبتتمسح أوتوماتيك.

شوف الكود ده وحدّد كل سطر هيروح فين:

int counter = 0;              // global  -> Data

int main() {                      // الكود نفسه -> Text
    int x = 5;                    // local   -> Stack
    int *p = malloc(100);        // 100 byte -> Heap
    // (المتغير p نفسه موجود على الـ Stack)
    free(p);                       // تحرير الـ Heap
}

٣) حالات الـ Process (Process States)

الـ Process مبتفضلش على حالة واحدة. وهي بتتنفذ بتمر بـ 5 حالات:

New 🆕 — لسه بتتعمل. (العميل دخل المطعم)

Ready ⏳ — جاهزة في الـ RAM وناقصها CPU بس. (واقفة في طابور الشيف)

Running ▶️ — بتتنفذ على الـ CPU دلوقتي. (الشيف شغال عليها)

Waiting ⌛ (أو Blocked) — مستنية حدث زي إدخال من الكيبورد أو قراءة ملف. (مستنية المكوّن يوصل)

Terminated 🏁 — خلصت. (الطلب اتسلّم)

⚠️ قاعدة مهمة: على CPU core واحد، Process واحدة بس تكون Running في نفس اللحظة.

٦) Scheduling والطوابير

الـ OS بيحط الـ Processes في طوابير: Job queue (كل الـ Processes)، Ready queue (اللي جاهزة للـ CPU)، وDevice queues (اللي مستنية I/O). الرسمة دي بتوضح الدورة:

أنواع الـ Schedulers

النوعبيعمل إيه؟بيشتغل كل قد إيه؟
Long-term (Job scheduler)بيختار Jobs من الـ Disk ويدخّلها الـ Memory (Ready queue). بيتحكم في degree of multiprogrammingنادراً (ثواني أو دقايق)
Short-term (CPU scheduler)بيختار Process من الـ Ready queue ويديها الـ CPUكتير جداً (ملّي ثانية) فلازم يكون سريع
Medium-termبيشيل Process من الـ Memory مؤقتاً (Swap out) ويرجّعها بعدين عشان يقلل الحملحسب الحاجة

نوعين من الـ Processes

I/O-bound: أغلب وقتها مستنية I/O (قراءة ملفات، شبكة) ومعاها bursts قصيرة على الـ CPU.

CPU-bound: أغلب وقتها حسابات على الـ CPU (زي معالجة فيديو) ومعاها I/O قليل.

Producer ⟶ Buffer مشترك ⟶ Consumer

Producer 🏭: بينتج بيانات (Items) ويحطها في الـ Buffer.

Consumer 🛒: بياخد البيانات من الـ Buffer ويستخدمها.

Buffer 📦: مساحة مشتركة. لو حجمه محدود اسمه Bounded Buffer.

المشاكل اللي لازم نحلها

1️⃣ الـ Buffer full: الـ Producer لازم يستنى (Waiting) لحد ما يتفضى مكان.

2️⃣ الـ Buffer empty: الـ Consumer لازم يستنى لحد ما يتحط Item.

3️⃣ الاتنين يدخلوا الـ Buffer في نفس اللحظة: بيحصل Race Condition (بيانات تضيع أو تتبوظ)، فلازم Synchronization (زي Mutex أو Semaphore) عشان واحد بس يعدّل في اللحظة.

مثال: Print Spooler 🖨️

🔹 3 برامج (Word و Browser و PDF reader) = Producers، كل واحد بيبعت Print Job.

🔹 الـ Print queue = Buffer، وفيه دلوقتي Job 1 و Job 2 و Job 3.

🔹 الـ Printer = Consumer، بيسحب Job ويطبعها.

🔹 ليه الـ Spooler؟ لأن الطابعة بطيئة، فالبرامج بتحط الـ Job في الطابور وتكمل شغلها من غير ما تستنى.

ملخص سريع قبل الأسئلة

  • Process = Program in execution. Program ساكن، Process نشط.
  • الذاكرة: Text, Data, Heap ⬆, Stack ⬇.
  • الحالات: New → Ready ⇄ Running → Terminated، ومن Running → Waiting → Ready.
  • PCB = ملف الـ Process (PID, State, PC, Registers, ...).
  • Context Switch = Save + Load، وده Overhead.
  • Long-term بيدخّل للـ Memory، Short-term بيدّي الـ CPU، Medium-term بيعمل Swapping.
  • IPC: Shared Memory أو Message Passing.
  • Producer–Consumer: Buffer مشترك. Producer يستنى لو full، Consumer يستنى لو empty، ولازم Synchronization عشان نمنع Race Condition. مثال: Print Spooler.

قاموس سريع

Interrupt — إشارة بتوقف الـ CPU مؤقتاً وتنده الـ OS.
Dispatch — إدّي الـ CPU لـ Process من الـ Ready.
Quantum — الوقت المسموح للـ Process على الـ CPU.
Overhead — وقت ضايع مفيهوش شغل مفيد.
PID — رقم الـ Process الفريد.
Multiprogramming — أكتر من Process في الذاكرة في نفس الوقت.
Blocked — نفس معنى Waiting.
Buffer — مساحة مؤقتة بيتبادل فيها الـ Producer والـ Consumer البيانات.
Race Condition — نتيجة غلط بتحصل لما أكتر من Process يعدّلوا نفس البيانات في نفس اللحظة.
